# Reinforcement Learning

## Summary

Reinforcement learning (RL) is the branch of machine learning concerned with sequential decision-making: an agent interacts with an environment over time, observing states, taking actions, and receiving reward signals, with the goal of learning a policy that maximizes cumulative reward. Unlike supervised learning, where labeled input-output pairs are provided, or unsupervised learning, where the system discovers structure in unlabeled data, RL learns from the consequences of its own actions through trial and error. This interaction-driven learning paradigm makes RL uniquely suited to problems where the right answer depends on context, unfolds over multiple steps, and can only be evaluated by experiencing the outcome.

RL has moved from a largely academic discipline to an essential tool in the ML engineer's repertoire. It powers game-playing agents that exceed human ability (AlphaGo, AlphaZero, OpenAI Five), drives the alignment of large language models through Reinforcement Learning from Human Feedback (RLHF), enables robotic manipulation and locomotion learned in simulation and transferred to real hardware, and optimizes complex sequential systems like recommendation engines, ad bidding platforms, and data center cooling. For a mid-career ML engineer, understanding RL means understanding when it is the right tool, how its methods relate to each other, and what practical challenges arise when deploying RL systems beyond toy environments.

Key points to remember:

- RL is a framework for learning sequential decision-making through interaction with an environment, not from a fixed dataset of labeled examples
- The RL loop consists of an agent observing a state, selecting an action, receiving a reward, and transitioning to a new state; this loop repeats until the task ends or continues indefinitely
- The agent's goal is to learn a policy (a mapping from states to actions) that maximizes expected cumulative discounted reward over time
- RL methods divide along three major axes: model-free vs. model-based, value-based vs. policy-based, and on-policy vs. off-policy
- Model-free methods (Q-Learning, DQN, PPO, SAC) learn directly from experience; model-based methods (Dreamer, MuZero) learn a model of the environment and use it to plan
- Value-based methods (DQN, Double DQN) learn a value function and derive a policy from it; policy-based methods (REINFORCE, PPO) optimize the policy directly
- On-policy methods (PPO, A2C) learn from data collected by the current policy; off-policy methods (DQN, SAC) can learn from data collected by any policy, enabling replay buffers and better sample efficiency
- RL is not always the right tool: it requires a well-defined reward signal, an environment to interact with (or a simulator), and is significantly more complex and sample-hungry than supervised learning
- The dominant practical algorithms today are PPO (for on-policy, continuous and discrete control, RLHF) and DQN variants (for discrete action spaces with replay)
- Reward engineering, simulation fidelity, and exploration strategy are often more important than algorithm choice

## How RL Differs from Other ML Paradigms

Understanding where RL sits relative to supervised and unsupervised learning clarifies when to use it and what to expect.

### Supervised Learning

In supervised learning, the training data consists of input-output pairs (x, y), and the model learns a mapping from inputs to outputs by minimizing a loss function that measures prediction error. The data is generated independently of the model (the model does not influence which examples it sees), the correct answer for each input is known, and the evaluation is straightforward.

### Unsupervised Learning

In unsupervised learning, the model receives inputs without labels and discovers structure: clusters, latent factors, density estimates, or compressed representations. There is no explicit feedback signal, and the model does not interact with an external system.

### Reinforcement Learning

RL differs from both paradigms in several fundamental ways:

| Dimension | Supervised Learning | Unsupervised Learning | Reinforcement Learning |
|---|---|---|---|
| Data source | Fixed dataset of labeled pairs | Fixed dataset without labels | Generated by agent-environment interaction |
| Feedback signal | Exact target for each input | None | Scalar reward, possibly delayed and sparse |
| Data distribution | Independent of model | Independent of model | Depends on the model's own decisions |
| Objective | Minimize prediction error | Discover structure | Maximize cumulative reward over time |
| Temporal structure | Typically none (i.i.d. samples) | Typically none | Sequential decisions with long-term consequences |
| Exploration | Not applicable | Not applicable | Central challenge: must balance trying new things with exploiting known good actions |

The most consequential difference is that in RL, the agent's actions affect the data it sees in the future. A policy that always turns left will never observe what happens after turning right. This coupling between decisions and data means that RL must solve a learning problem and an exploration problem simultaneously.

### When RL Is the Right Paradigm

RL is the right choice when the following conditions hold:

- The problem involves sequential decisions where actions have consequences that unfold over time
- There is a clear reward signal (or one can be constructed) that captures the objective
- The optimal decision depends on the current context (state) and cannot be reduced to a static input-output mapping
- An environment or simulator exists for the agent to interact with during training

Common applications include game-playing, robotic control, dialogue systems, recommendation with long-term user engagement, resource allocation, and LLM alignment via RLHF.

### When RL Is Overkill

RL is often the wrong choice when:

- The problem can be framed as supervised learning (e.g., classification, regression with available labels)
- Decisions are independent and do not affect future states (single-step optimization, bandit problems may suffice)
- No simulator or environment is available, and real-world interaction is too expensive or dangerous for the exploration RL requires
- The reward signal is ambiguous, undefined, or would require as much engineering effort as solving the problem directly
- Sample efficiency is critical and only a small amount of data is available (supervised learning or imitation learning is usually more appropriate)

A common mistake is reaching for RL when a simpler approach would work. If you have labeled data and a clear loss function, use supervised learning. If you have expert demonstrations and a stable environment, behavioral cloning may suffice. RL is most valuable when the problem genuinely requires sequential reasoning under uncertainty and no simpler formulation captures the objective.

## The RL Loop: Agent, Environment, State, Action, Reward

The structure of every RL problem follows the same interaction loop, regardless of the specific algorithm or application domain.

```
The RL Interaction Loop:

   +-------+    action a_t    +-----------+
   |       | ---------------> |           |
   | Agent |                  |Environment|
   |       | <--------------- |           |
   +-------+  state s_{t+1}  +-----------+
               reward r_t
```

At each time step t:

1. The agent observes the current state s_t of the environment
2. The agent selects an action a_t according to its policy pi(a_t | s_t)
3. The environment transitions to a new state s_{t+1} according to its dynamics
4. The environment emits a reward r_t that evaluates how good the action was
5. The agent uses this experience (s_t, a_t, r_t, s_{t+1}) to update its policy
6. The loop repeats from the new state

The components of this loop are:

**Agent.** The learner and decision-maker. The agent contains the policy (its strategy for selecting actions), and possibly a value function (its estimate of how good each state or action is) and/or a model of the environment. Everything the agent learns is encoded in these components.

**Environment.** Everything outside the agent. The environment defines the rules of the world: what states exist, what transitions are possible, and what rewards are given. The environment may be a physical system (a robot's workspace), a simulator (a game engine), or an abstraction (a recommendation platform modeled as an MDP). The agent cannot change the environment's rules; it can only observe and act within them.

**State.** A description of the current situation. In a board game, the state is the board position. In robotics, it is the joint angles, velocities, and sensor readings. In LLM alignment, it is the conversation history. The state should contain enough information for the agent to make a good decision (the Markov property: the future depends only on the current state and action, not on the history).

**Action.** What the agent can do. Actions may be discrete (move left, right, up, down) or continuous (apply a specific torque to a motor). The action space defines the set of all possible actions at each state.

**Reward.** A scalar signal from the environment indicating how good the last action was. The reward is the only feedback the agent receives. Designing good reward functions is one of the hardest and most important aspects of applying RL in practice. Rewards may be dense (given at every step) or sparse (given only at task completion), immediate or delayed.

**Policy.** The agent's strategy, mapping states to actions (deterministic) or to probability distributions over actions (stochastic). The policy is what RL algorithms optimize.

**Value function.** An estimate of the expected cumulative reward from a given state (V(s)) or state-action pair (Q(s, a)). Value functions allow the agent to evaluate long-term consequences rather than just immediate reward.

## Taxonomy of RL Methods

RL algorithms can be organized along three orthogonal axes. Understanding these axes is essential for navigating the literature and choosing the right approach for a given problem.

### Axis 1: Model-Free vs. Model-Based

**Model-free methods** learn a policy or value function directly from experience without building an explicit model of the environment's dynamics. The agent treats the environment as a black box: it sends actions in and receives states and rewards back, never attempting to predict what will happen before it acts.

- Value-based model-free: Q-Learning, DQN, Double DQN, Dueling DQN
- Policy-based model-free: REINFORCE, PPO, TRPO
- Actor-critic model-free: A2C, A3C, SAC, TD3

Model-free methods are simpler to implement and do not accumulate model prediction errors. Their disadvantage is sample inefficiency: the agent must interact extensively with the environment because it cannot "imagine" outcomes.

**Model-based methods** learn or are given a model of the environment (transition dynamics and reward function) and use it to plan. The agent can simulate the consequences of actions before taking them, which dramatically improves sample efficiency.

- World models: Dreamer (V1, V2, V3), which learn latent dynamics and train policies in imagination
- Search-based: MuZero, AlphaZero, which use Monte Carlo Tree Search with learned models
- Dyna-style: Methods that augment real experience with synthetic rollouts from a learned model

Model-based methods are more sample-efficient but introduce the challenge of model error: predictions that diverge from reality compound over multi-step planning horizons.

### Axis 2: Value-Based vs. Policy-Based

**Value-based methods** learn a value function (typically Q(s, a)) and derive a policy by selecting the action with the highest value: pi(s) = argmax_a Q(s, a). They work best with discrete action spaces because the argmax requires enumerating all possible actions.

- Q-Learning, DQN, Double DQN, Dueling DQN, Rainbow

**Policy-based methods** directly parameterize the policy (e.g., with a neural network) and optimize it via gradient ascent on expected return. They naturally handle continuous action spaces and can represent stochastic policies.

- REINFORCE, PPO, TRPO

**Actor-critic methods** combine both: an actor (policy network) selects actions, and a critic (value network) evaluates them. The critic reduces variance in policy gradient estimates, while the actor handles continuous or stochastic action selection. Most modern deep RL systems use actor-critic architectures.

- A2C, A3C, PPO (with a value baseline), SAC, TD3, DDPG

### Axis 3: On-Policy vs. Off-Policy

**On-policy methods** learn about the policy currently being used to collect data. Old experience becomes stale whenever the policy changes, so it must be discarded after each update. This is less sample-efficient but simpler and more stable.

- SARSA, REINFORCE, A2C, PPO

**Off-policy methods** learn about one policy (typically the optimal policy) while following a different policy (typically one that explores more). This allows reuse of old experience through replay buffers, improving sample efficiency at the cost of added complexity.

- Q-Learning, DQN, SAC, TD3, DDPG

### How the Axes Interact

These axes are orthogonal but not all combinations are equally common in practice:

| Method | Model-Free/Based | Value/Policy | On/Off-Policy |
|---|---|---|---|
| Q-Learning | Model-free | Value-based | Off-policy |
| DQN | Model-free | Value-based | Off-policy |
| REINFORCE | Model-free | Policy-based | On-policy |
| PPO | Model-free | Actor-critic | On-policy |
| SAC | Model-free | Actor-critic | Off-policy |
| Dreamer | Model-based | Actor-critic | Off-policy |
| MuZero | Model-based | Value + Policy (via search) | Off-policy |

## Where RL Is Used Today

### Game Playing

Games have been the proving ground for RL since the field's inception. The controlled, deterministic (or well-defined stochastic) rules of games make them ideal testbeds. Milestones include:

- **Atari (DQN, 2015):** DQN achieved human-level performance on many Atari 2600 games from raw pixel input, demonstrating that deep RL could handle high-dimensional observations with discrete actions.
- **Go (AlphaGo/AlphaZero, 2016-2017):** AlphaGo defeated the world champion in Go, a game long considered intractable for AI. AlphaZero learned to play Go, chess, and shogi from self-play alone, with no human expert data.
- **Dota 2 (OpenAI Five, 2019):** A team of five RL agents defeated professional players in a complex, real-time, partially observable team game with long time horizons.
- **StarCraft II (AlphaStar, 2019):** Reached Grandmaster level in a real-time strategy game requiring long-term planning, imperfect information, and large action spaces.

### Robotics

RL enables robots to learn complex manipulation and locomotion skills that are difficult to program manually. Sim-to-real transfer (training in simulation, deploying on real hardware) has made RL practical for robotics by avoiding the sample inefficiency problem on physical hardware. Applications include dexterous hand manipulation, legged locomotion, drone navigation, and assembly tasks.

### Recommendation Systems

Recommendation can be framed as a sequential decision problem where the system (agent) selects items to show (actions) based on user context (state) to maximize long-term engagement or satisfaction (reward). RL captures the sequential nature of user interaction better than static supervised models, which optimize for immediate click-through without considering how recommendations shape future user behavior.

### RLHF for Large Language Models

Reinforcement Learning from Human Feedback has become the standard approach for aligning large language models with human preferences. The pipeline is:

1. Train a reward model from human preference comparisons (which response is better?)
2. Fine-tune the language model using RL (typically PPO) to maximize the reward model's score while staying close to the base model

This approach is used by InstructGPT, ChatGPT, Claude, Llama, and most modern instruction-following LLMs. The reward modeling step is a form of inverse reinforcement learning, and the fine-tuning step is standard policy optimization. RLHF has made RL directly relevant to every ML engineer working on language models.

### Autonomous Systems

Autonomous vehicles, industrial process control, data center cooling, network routing, and supply chain optimization all involve sequential decisions where actions have delayed consequences. RL provides a framework for learning policies that optimize these systems over time. Google used RL to reduce data center cooling energy consumption by 40%. Autonomous driving systems use RL components for planning and decision-making alongside rule-based safety systems.

### Finance and Trading

Portfolio optimization, order execution, and market making involve sequential allocation decisions under uncertainty with delayed feedback. RL agents can learn strategies that adapt to changing market conditions, though deployment in live markets requires careful handling of non-stationarity and risk constraints.

## Practical Considerations

### Reward Engineering

Designing the reward function is often the hardest part of applying RL. The reward must capture the true objective, but specifying exactly what you want in a scalar signal is surprisingly difficult. Common pitfalls include:

- **Reward hacking:** The agent finds an unintended way to accumulate reward without solving the real task. A cleaning robot rewarded for "not seeing dirt" may learn to avoid looking at the floor.
- **Sparse rewards:** If reward is given only at task completion (e.g., winning a game), the agent receives no learning signal until it accidentally stumbles on success, which may never happen in complex environments.
- **Reward shaping:** Adding intermediate rewards to guide learning can help but risks changing the optimal policy if done incorrectly. Potential-based reward shaping (Ng et al., 1999) is the theoretically safe approach.
- **Multi-objective tradeoffs:** Real-world tasks often involve multiple competing objectives (speed vs. safety, engagement vs. diversity). Encoding these tradeoffs in a single scalar reward requires weighting decisions that are themselves part of the problem.

When reward engineering becomes intractable, inverse reinforcement learning (learning the reward function from expert demonstrations) and RLHF (learning the reward function from human preferences) provide alternatives. See the [Inverse Reinforcement Learning](inverse-reinforcement-learning/) child chapter.

### Simulation Requirements

Most modern RL requires millions to billions of environment interactions during training. This is only feasible if the environment can be simulated fast and cheaply. When simulation is available:

- Training happens entirely in simulation, with policies transferred to the real world (sim-to-real)
- The fidelity of the simulator directly affects the quality of the transferred policy
- Domain randomization (varying simulator parameters during training) helps policies generalize across the sim-to-real gap

When simulation is not available or too expensive:

- Sample-efficient methods (model-based RL, offline RL) become essential
- Behavioral cloning from expert demonstrations may be a better starting point
- Offline RL can learn from logged data without further environment interaction

### When RL Is Overkill: A Decision Checklist

Before committing to RL, ask:

1. Can this be solved with supervised learning? If you have input-output examples and the problem does not involve sequential decisions, supervised learning is simpler, more sample-efficient, and better understood.
2. Is a greedy or myopic policy sufficient? If the optimal action at each step does not depend on future consequences, you do not need RL. A contextual bandit or simple optimization may suffice.
3. Do I have a simulator? Without one, RL training requires real-world interaction, which is often too slow, expensive, or dangerous.
4. Can I define a good reward function? If not, consider whether inverse RL or RLHF could help, or whether the problem is better approached with imitation learning.
5. Is the problem stationary enough? If the environment changes faster than the agent can learn, RL may not converge to a useful policy.

### Exploration and Sample Efficiency

Exploration -- trying actions the agent is uncertain about -- is essential for RL to work but comes at a cost. Every exploratory action that yields a bad outcome is a wasted interaction from the perspective of immediate performance. The exploration-exploitation tradeoff is the central practical challenge of RL, and choosing the right exploration strategy is often more important than choosing the right algorithm.

For a detailed treatment of exploration methods, from epsilon-greedy to curiosity-driven exploration, see the [Concepts](concepts/) child chapter.

### Stability and Reproducibility

RL training is notoriously unstable and sensitive to hyperparameters, random seeds, and implementation details. The same algorithm with the same hyperparameters can produce dramatically different results across runs. This makes RL harder to debug, evaluate, and deploy than supervised learning.

Practical advice:

- Always run multiple random seeds and report aggregate statistics, not cherry-picked results
- Use well-tested implementations (Stable Baselines3, CleanRL, RLlib) rather than writing your own unless you have a specific reason
- Monitor training with reward curves, value function estimates, entropy, and gradient norms
- Start with PPO as a default algorithm; it is the most robust to hyperparameter choices

## Roadmap Through the Child Chapters

This chapter provides the big picture. The child chapters go deep on specific areas. The following learning path provides a logical progression.

### 1. Foundations: Concepts

Start here. The [Concepts](concepts/) chapter covers the mathematical foundations that every RL algorithm builds on:

- **Markov Decision Processes (MDPs):** The formal framework for RL problems, including states, actions, transitions, rewards, and the discount factor
- **Bellman Equations:** The recursive equations that express value functions and enable every RL algorithm, from tabular Q-learning to deep policy optimization
- **Exploration vs. Exploitation:** The fundamental challenge of balancing information gathering with reward maximization, including epsilon-greedy, UCB, Thompson Sampling, and intrinsic motivation

These three topics form an integrated framework. MDPs define the problem, Bellman equations provide the solution structure, and exploration strategies provide the learning mechanism.

### 2. Value-Based Methods

The [Value-Based Methods](value-based-methods/) chapter covers algorithms that learn a value function and derive a policy from it:

- **Q-Learning:** The foundational tabular algorithm with convergence guarantees
- **DQN:** Scaling Q-learning to high-dimensional observations with neural networks, experience replay, and target networks
- **Double DQN:** Fixing the overestimation bias inherent in the max operator
- **Dueling DQN:** Separating state value from action advantage for better representation

This family is best suited to discrete action spaces and problems where off-policy learning and replay buffers provide a sample efficiency advantage.

### 3. Policy-Based Methods

The [Policy-Based Methods](policy-based-methods/) chapter covers algorithms that directly optimize a parameterized policy:

- **REINFORCE:** The simplest policy gradient algorithm, useful for understanding the fundamentals
- **Actor-Critic:** Introducing a value function (critic) to reduce variance in policy gradient estimates
- **A2C/A3C:** Scaling actor-critic with parallel workers
- **TRPO:** Trust region constraints for stable policy updates
- **PPO:** The dominant practical algorithm, combining stability with simplicity

This family handles continuous action spaces, stochastic policies, and is the basis for RLHF in language model alignment.

### 4. Model-Based RL

The [Model-Based RL](model-based-rl/) chapter covers methods that learn or leverage a model of the environment:

- **World Models (Dreamer):** Learning latent dynamics models and training policies entirely in imagination
- **MuZero:** Learning a model optimized for planning-relevant predictions, combined with Monte Carlo Tree Search

Model-based methods offer dramatically better sample efficiency (10-100x fewer environment interactions) at the cost of model accuracy challenges. They are the right choice when real-world interaction is expensive.

### 5. Multi-Agent RL

The [Multi-Agent RL](multi-agent-rl/) chapter extends RL to settings with multiple interacting agents:

- Cooperative, competitive, and mixed settings
- Centralized training with decentralized execution (CTDE)
- Key algorithms: QMIX, MAPPO, MADDPG
- Self-play for competitive settings
- Communication between agents

Multi-agent RL is relevant to robotics coordination, game AI, traffic systems, and market design.

### 6. Inverse Reinforcement Learning

The [Inverse Reinforcement Learning](inverse-reinforcement-learning/) chapter covers learning the reward function from demonstrations:

- Maximum Entropy IRL
- Generative Adversarial Imitation Learning (GAIL)
- The connection to RLHF and language model alignment
- When to use IRL vs. behavioral cloning vs. standard RL

IRL is essential for problems where specifying a reward function is harder than demonstrating the desired behavior.

### 7. Frameworks

The [Frameworks](frameworks/) chapter covers the practical tools for implementing RL systems:

- **Stable Baselines3:** Production-quality implementations with a high-level API, the default choice for single-agent single-machine training
- **RLlib:** Scalable distributed training with native multi-agent support, built on Ray
- **CleanRL:** Single-file implementations with no abstractions, ideal for understanding algorithms and research prototyping

## Algorithm Selection Guide

For practitioners choosing an approach, the following guide covers the most common scenarios:

```
Start
  |
  v
Is the problem sequential (actions affect future states)?
  |
  +-- No --> Do not use RL. Use supervised learning, bandits, or optimization.
  |
  +-- Yes --> Continue
  |
  v
Do you have expert demonstrations but no reward function?
  |
  +-- Yes --> Consider Inverse RL or Behavioral Cloning (see IRL chapter)
  |
  +-- No --> Continue
  |
  v
Is the action space discrete or continuous?
  |
  +-- Discrete --> Value-based methods (DQN variants) or PPO
  |
  +-- Continuous --> Policy-based / actor-critic methods (PPO, SAC, TD3)
  |
  v
Is sample efficiency critical (expensive environment interactions)?
  |
  +-- Yes --> Model-based methods (Dreamer, MuZero) or off-policy methods (SAC, DQN)
  |
  +-- No --> On-policy methods (PPO) are simpler and more stable
  |
  v
Are there multiple interacting agents?
  |
  +-- Yes --> Multi-agent methods (MAPPO, QMIX, MADDPG)
  |
  +-- No --> Single-agent methods
  |
  v
Default recommendation: Start with PPO. It works across discrete and continuous
action spaces, is robust to hyperparameters, and has excellent library support.
```

### Quick Reference Table

| Scenario | Recommended Approach |
|---|---|
| Discrete actions, moderate state space | DQN or Double DQN |
| Discrete actions, image observations | DQN with CNN encoder |
| Continuous control (robotics, physics) | PPO or SAC |
| LLM alignment / RLHF | PPO with reward model |
| Sample-efficient learning | Model-based (Dreamer, MuZero) |
| Multiple cooperating agents | MAPPO or QMIX |
| Multiple competing agents | Self-play with PPO |
| Learning from demonstrations | GAIL or behavioral cloning |
| Reward function is hard to specify | Inverse RL or RLHF |
| Offline learning from logged data | CQL, IQL (offline RL) |
| Default starting point | PPO |

## Key Terminology

- **Agent:** The learner and decision-maker in an RL system
- **Environment:** Everything the agent interacts with; defines the rules, states, transitions, and rewards
- **State (s):** A description of the current situation sufficient for decision-making
- **Action (a):** A choice available to the agent at each time step
- **Reward (r):** A scalar feedback signal evaluating the last action
- **Policy (pi):** The agent's strategy, mapping states to actions or action distributions
- **Value function V(s):** The expected cumulative reward from state s under a given policy
- **Action-value function Q(s, a):** The expected cumulative reward from taking action a in state s
- **Return (G):** The cumulative discounted reward from a given time step onward
- **Discount factor (gamma):** A scalar in [0, 1] that controls how much the agent values future vs. immediate rewards
- **Episode:** A complete sequence of interaction from start to terminal state
- **Exploration:** Trying actions the agent is uncertain about to gather information
- **Exploitation:** Choosing the action the agent currently believes is best
- **Replay buffer:** A data structure storing past experience for reuse in off-policy learning
- **Bellman equation:** The recursive equation relating the value of a state to the values of its successors
- **Temporal difference (TD) learning:** Updating value estimates based on other value estimates (bootstrapping)
- **Advantage A(s, a):** How much better action a is compared to the average action in state s: A(s, a) = Q(s, a) - V(s)
